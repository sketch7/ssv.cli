# `ssv link` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a safe, reversible, pnpm-focused `ssv link` command and `ssv link init` workflow with deterministic dry runs, generated Valibot schema, and comprehensive Vitest coverage.

**Architecture:** Commander delegates to focused link modules. Read-only discovery feeds a pure, deterministic reconciliation planner; an executor applies guarded build/filesystem actions and atomically persists validated state. Dry run renders the same plan without process execution or writes.

**Tech Stack:** Node.js 24, TypeScript 7, Commander 15, Valibot 1, YAML 2, consola 3, execa 10, Vitest, `@vitest/coverage-v8`, tsdown, oxlint, and oxfmt.

## Global Constraints

- Use `ssv` naming exclusively in production code, file names, configuration, state, backups, output, and documentation.
- Public names are `ssv link`, `ssv link init`, `.ssv-links.yaml`, `.ssv-links.state.json`, and `ssv-links.config.schema.json`.
- Default consumer root is `process.cwd()`; `--root <path>` overrides it.
- Support pnpm only; do not modify `package.json`, `pnpm-workspace.yaml`, or lockfiles.
- `.ssv-links.yaml` is commit-friendly; only state and backup artifacts are added to `.gitignore`.
- Configuration and state types must be inferred from Valibot schemas.
- Generated JSON schemas are never edited manually.
- Every consumer mutation must remain inside the resolved consumer root.
- Use ESM, `node:` built-in imports, consola with `consola/utils` colors, and execa for child processes.
- Use TDD for every behavior change and keep temporary fixtures outside the real repository tree.
